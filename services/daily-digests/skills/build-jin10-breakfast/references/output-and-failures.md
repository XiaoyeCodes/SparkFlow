# 输出、原文保真与失败处理

## 原文处理

读取金十专题343，按北京时间当天标题选文章。SSR标题/导语和Nuxt JSON字面量元数据必须一致，发布时间也必须是目标日期；解析器支持`$`变量而不执行JS。音频行仅在文字全部属于已知语言/下载标签时移除。未知媒体或伴随正文必须失败检查。

市场收盘表以“市场盘点”和“国际要闻”之间的唯一图识别，仅移除该图；其他原网页图片也不下载不展示，但含文字的图注/图容器不静默删正文。包内顶部插画保持。保留所有新闻文本、段落、粗体和列表；渲染前后比较整个正文文本及段落、粗体数组。原文发生真实结构变化时先审查再改解析器，不把缺段当成功。

五个既有主区块为今日优选、市场盘点、国际要闻、国内要闻、风险预警。新增/改名主区块触发结构复核。导语、原文标题、免责声明和来源页脚独立保存。生成不是摘要改写。

## 状态

- awaiting_market_data：正文已验证，行情尚未装配，不能交付为完成。
- ready：9项全部通过；仍不表示所有源同步实时。
- ready_degraded：部分缺失，表内显示“暂无可信报价”和“—”。告知未齐，不复用上一期。
- market_data_error：全缺失/输入绑定失败/过期，不能将旧文件作为本次产物。
- no_update：专题成功打开但没有当天文章；不发前日。
- access_error：访问失败；不是无更新，不绕过拒绝。
- structure_error/date_mismatch/validation_error：不能确认完整或正确日期，停止当前稿并说明。
- preview_only：显式历史/版式演示，ready永远false。

行级行情失效必须清除数值。每次新的目录，收件/发布方必须先检查当前status.json。技能只生成文件，不发送任何邮件、不创建或修改排程。

## 检查

运行单元测试。查看独立HTML的桌面和手机宽度；9行完整，数值列统一，涨跌靠右，无原收盘表，只有顶部插画。PDF须检查每页PNG、全部新闻文本核对和嵌入中文字体，不把静态预览当作真实邮件客户端测试。
