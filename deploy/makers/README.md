# SparkFlow 的 Makers 部署核对

本次要求：保留全部页面、行情、新闻、日报、策略研究、AI 和 IBKR 的代码与入口；不上传个人配置、密钥、账户记录、聊天、运行缓存或 `output/`。AI 密钥留空，IBKR 不建立连接。

## 已确认的运行依赖

| 模块 | 当前实现 | 部署前必须处理的事项 |
| --- | --- | --- |
| 页面与静态资源 | React / Vite，路由定义在 `src/App.tsx` | Makers 可以托管构建产物；所有路由均保留 |
| 行情、新闻、宏观数据 | `vite.config.ts` 的 Node 中间件 | `vite build` 不会把这些接口变成云函数，需要独立后端入口 |
| 刷新与预加载 | 常驻进程中的定时器、队列与内存缓存 | 云函数响应后不能依赖后台进程继续运行，需要平台调度并等待任务落盘 |
| 持久缓存 | `.sparkflow/` 和 `UserData/reports/` 的文件与原子重命名 | 云端需要持久存储；不能把临时目录视为持久缓存 |
| 每日资讯 | Python 子进程，最长 240 秒；北京时间 08:00 / 09:00 / 18:00，启动补跑 | Python 生成器、调度、日期校验和缓存均需迁移，不能只保留阅读界面 |
| 每日简报 | 整点生成、失败重试、文件锁与选择性修复 | 应保留每小时更新；实例冷启动后能恢复上次成功版本 |
| 策略研究 | 独立 Python 环境、NDJSON 子进程和长任务 | 包含科学计算与原生依赖，不能直接作为普通 Node 云函数的子进程环境 |
| AI 助手 | `services/vibe-trading`，Python >= 3.11、FastAPI、长任务及文件导出 | 入口和代码保留；空密钥时不发起模型调用，后续配置前要验证运行环境 |
| IBKR | 本地请求限制、MCP / Gateway、账户文件和后台任务 | 默认断开；公网部署不能把访问者的 `127.0.0.1` 当成云端 Gateway |
| 设置、账户与会话 | 单机用户数据模型 | 公网前必须加访问隔离，避免任何访客都能读取或修改同一套配置、密钥与账户数据 |
| PDF 阅读与导出 | 文件流、Range、原生依赖 | 普通云函数的响应大小限制不能截断 PDF；需验证静态文件或对象存储的 Range 支持 |

## 平台边界（核对于 2026-10-28）

Makers 普通 Cloud Functions 的公开限制为：代码与依赖 128 MB，请求/响应 6 MB，单次执行最长 120 秒，Python 运行时为 3.10。项目的原后台不是静态网站，不能直接上传 `dist/` 后声明完整部署。

- [Cloud Functions 官方文档](https://pages.edgeone.ai/zh/document/cloud-functions)
- [持久化 Blob 官方文档](https://pages.edgeone.ai/zh/document/blob-storage)
- [调度配置官方文档](https://pages.edgeone.ai/zh/document/edgeone-json)
- [Agents 官方文档](https://pages.edgeone.ai/zh/document/agents)

Agents 支持较长任务与沙箱，可作为进一步迁移的候选运行单元，但不等于可以直接托管现有常驻服务。其会话生命周期、存储、依赖打包及鉴权仍需单独适配和线上验证。

本机现有 Python 依赖目录的实测大小：AI 研究服务约 792 MB，策略研究约 533 MB。这是 Windows 已安装目录的体积，不代表 Linux 打包结果；它说明不能把当前虚拟环境直接放进 128 MB 的普通云函数包，仍须重新构建和验证。

调度文档同时列出“每小时整点”示例和“最小间隔一天”的说明；实际可用频率需要在账号下验证，不能提前承诺与本机定时器等价。

## 干净导出

在源码目录执行：

```powershell
node scripts/prepare-clean-deployment.mjs --out D:/Temp/SparkFlow-clean-source-20261028
```

脚本只导出 Git 跟踪源码及部署工具本身，不遍历复制整个工作目录。不覆盖已有目录，不修改本机个人设置；导出前检查常见明文凭据，发现问题时只报告文件与行号，不输出凭据。

导出副本还会清空源码和示例环境文件中预置的个人 Coze 服务地址与项目编号，保留完整的对接代码。本机源码中的原有默认值不被修改；这些导出调整逐项记录在清单中。

`deployment-manifest.json` 保留每个导出文件的 SHA-256，供上传前复核。它明确标识这是源码导出，并未完成后端运行适配；不能把此目录直接当成“完整可用的 Makers 版本”。

构建和云端启动均设置 `SPARKFLOW_IMPORT_LEGACY_DATA=0`，防止 `initializeUserData()` 在构建机器上自动导入桌面遗留密钥、会话或账户。此开关默认不影响本机现有的迁移行为。

## 上线验收门槛

1. 全部原有页面可访问，AI 与 IBKR 入口保留，个人设置和密钥为空。
2. 公共 API 在云端工作，关闭本机服务后行情、新闻和宏观数据仍能更新。
3. 缓存跨云实例重启恢复，不泄露个人配置或账户数据。
4. 简报按北京时间每小时更新；三类日报按原时间生成、过点补跑、来源未发布时保留上次成功版本。
5. 并行请求合并、超时、备用源、数据日期与错误状态正常；不得用静态假数据掩盖加载失败。
6. 未登录访客不能读写私有配置、会话、账户或触发账户操作。
7. PDF、SSE、长研究任务和导出经过云端实测；尚未验证的能力必须如实标明。

如果采用“Makers 前端 + 常驻云后端”，可以沿用大部分现有后台与文件锁逻辑，但需要另行开通具备持久卷的计算资源，并在正式创建收费资源前确认费用。这与“全部运行在 Makers Functions”是两种不同架构，不能未经确认替换。
