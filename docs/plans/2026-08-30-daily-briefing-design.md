# SparkFlow 每日简报设计

## 目标

在 `/council` 建立一个适合个人投资者每天查看两次的市场简报页。信息结构参考 Day1 Global Briefing 的“先结论、后证据”，视觉以用户提供的 `dashboard_redesign.html` 为主：蓝黑背景、克制的青蓝高光、半透明圆角卡片、紧凑但不拥挤的数据排版。

页面不提供量化交易信号、回测、自动下单或“抄底/逃顶”判断。它回答四件事：市场发生了什么、为什么值得关注、与我的持仓有什么关系、今天应该继续观察什么。

## 页面结构

1. 顶部导语：日期、早报/晚报状态、缓存时间与更新按钮。
2. 核心市场带：A 股、港股、美股、VIX、黄金、比特币。这里展示最新行情，不被每日快照缓存限制。
3. 每日结论：一句话环境判断、三条重点、三条风险/观察项。
4. 市场情绪：涨跌分布、VIX、美元、美债、黄金和加密资产的方向摘要。
5. 我的持仓：IBKR 只读同步。未连接时保持安静的引导状态，不伪造持仓结论。
6. 重点新闻：当天高权重新闻，保留来源、时间和原文链接。
7. 页尾数据说明：列出快照时点、实时数据时点、失败/陈旧来源。

页面内用 hash 切换 `#overview`、`#sentiment`、`#portfolio`、`#news`，便于书签和分享。

## 数据与缓存

- 实时层：复用 SparkFlow 现有 `/api/global-macro-quotes`、热力图与新闻接口。热力图、指数和加密资产继续按原有高频策略刷新。
- 简报层：08:00 与 18:00（Asia/Shanghai）各生成一个日期化快照。存储路径为 `.sparkflow/daily-brief/YYYY-MM-DD/{morning|evening}.json`。
- 首次打开：当天对应时段没有快照时生成一次；有快照时直接读取，避免重复抓取。
- 并发：进程内 Promise 去重，进程间采用独占锁文件；过期锁自动回收。
- 容错：所有数据并发聚合，单一来源失败不阻断简报；保留 last-good 值并明确标记，不把缺失值替换成 0。
- 历史：保留 90 天，`latest.json` 只作为快速索引，不能替代日期校验。

## AI 总结

AI 输入只包含带来源和时间戳的市场数据、新闻摘要与可选的 IBKR 持仓，不包含硬编码仓位。输出限制为可验证的中文 JSON：环境判断、三条重点、风险、关注事项、持仓提示。

服务端读取 `DAILY_BRIEF_AI_PROVIDER`、`DAILY_BRIEF_AI_BASE_URL`、`DAILY_BRIEF_AI_MODEL`、`DAILY_BRIEF_AI_API_KEY`。未配置或请求失败时使用确定性摘要，页面明确显示“规则摘要”，不会展示伪造的 AI 结果。

## 调度

- 运行中的 SparkFlow 服务按上海时区计算下一次 08:00/18:00，并在进程内触发。
- GitHub Actions 在 00:00 和 10:00 UTC 调用受 Bearer Token 保护的刷新接口，作为公网部署的冗余触发器。
- GitHub Actions 使用 `SPARKFLOW_BRIEFING_URL` 与 `DAILY_BRIEF_CRON_SECRET` 仓库 Secrets；服务端使用同名 secret 验证。
- 定时任务具备日期/时段锁，多次触发只会生成一次。

## 隐私与安全

IBKR 仍通过本机只读 Bridge 获取，不保存用户名、密码或会话凭据。每日快照只保存展示所需的证券代码、数量和成本摘要，不返回完整账户号。公网部署应在反向代理层增加访问认证；定时刷新接口必须配置 secret，否则只允许本机请求。

## 参考与归属

数据并发、日期锁、定时冗余和“事实数据与 AI 结论分离”的思路参考 MIT 许可的 `star23/day1global-briefing`。SparkFlow 的页面结构、样式和组件独立实现，视觉以用户提供的 HTML 为主。
