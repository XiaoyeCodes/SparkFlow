# SparkFlow IBKR 智能交易终端实施计划书

> 面向 Codex 长期目标执行。版本：1.0；日期：2026-09-04；当前状态：仅完成规划，尚未启动本计划的开发或交易操作。

**目标：** 严格沿用用户提供的 HTML 布局，将现有 IBKR 只读页面升级为流畅、简约、墨绿科幻风的交易终端，支持真实 IBKR 模拟盘与实盘、用户定义的量化策略、历史回测，以及账户 AI 分析和报告。

**架构：** React 页面 + 独立运行的本地交易服务 + IB Gateway/TWS。优先复用现有 Python 连接器、回测和风控模块，通过持久化订单状态与隔离的账户权限补齐 IBKR 链路；AI 不直接控制订单执行。

**技术栈：** 现有 React / TypeScript / Vite、lightweight-charts、Python / FastAPI、现有 ib_async 适配层；本地 SQLite 用于交易事件和任务持久化。具体 SDK 版本在实施前验证并锁定。

## 4. 第一部分：性能目标与更新机制

先在用户实际机器记录浏览器、视口、构建版本和基线；以下是待实测的验收目标，不是当前成绩。

- 生产构建、本地服务、固定测试数据：首屏主要内容 LCP ≤2.5s；常用点击反馈 p95 ≤100ms，交互延迟 INP 目标 ≤200ms。
- 在 50 个持仓、500 条订单、10,000 根 K 线条件下，拖拽／滚动目标接近 60fps；不出现持续主线程卡顿。大表虚拟化或分页。
- 行情通过持久连接增量推送，前端按 100–250ms 合并可视更新；不能每个 tick 重绘全页面。订单与风控事件不丢弃、不按行情方式合并。
- 本地服务收到事件至页面显示 p95 ≤250ms；券商网络延迟另外统计，不能把界面响应等同成交速度。
- 新闻、宏观、AI、回测独立加载与失败隔离。回测在独立 worker 执行，不能阻塞交易事件循环。
- 后台页面降低行情绘制频率；策略运行由本地服务承担，不能依赖浏览器标签保持开启。
- 行情明确区分实时、延迟、冻结、断线与缺失。缓存不能冒充新行情；用于开仓的数据超过策略允许时效则拒绝。
- 账户事件推送加定期对账；建议健康检查 5s、对账 30–60s，实际服从 API 限流。宏观沿用现有缓存策略，新闻按来源独立缓存，AI 按需执行。
- 进行 60 分钟连续运行测试：记录内存、请求数、连接数、事件队列；不出现订阅泄漏或无限增长。临时截图、日志和测试浏览器目录继续排除文件监听。

## 6. 第三部分：账户、订单与量化

### 6.1 服务与账户隔离

采用本地模块化服务，先不引入微服务集群。浏览器只访问受保护的本地 HTTP/WebSocket API，交易服务持有 IBKR 连接。Vite 只承担开发代理，不承载可靠交易生命周期。

保留现有只读连接器；新增可写适配层与显式能力配置，不把所有 readonly 标志批量改为 false。paper、live、backtest 三个命名空间隔离账户映射、缓存、授权、事件和报告。

账户绑定必须结合明确配置、券商返回账户和用户确认；端口或账户前缀不能单独充当实盘防护。默认只读，切换实盘视图不等于启用实盘交易。用户名、密码与 MFA 留在官方 Gateway/TWS；不写入网页、仓库或 AI 提示词。

交易服务绑定 loopback，校验 Origin/Host、会话和写请求授权，防止其他网页调用本地交易接口。敏感配置使用系统安全存储；账户数据目录限制访问。数据库、日志、报告不提交 Git。后续远程部署必须另行设计 TLS、认证和网络边界。

IBKR 模拟盘可以通过 API 使用，但成交是模拟，不能视为真实流动性的证明。行情权限也需要单独核验。[模拟盘说明](https://www.interactivebrokers.com/campus/glossary-terms/paper-trading-account/)；[行情订阅说明](https://www.interactivebrokers.com/docs/general/market-data-subscriptions/introduction)。

### 6.2 统一订单流水线

手动表单／已授权策略 → 标准订单意图 → 账户与授权检查 → 风控与资金预占 → 持久化 → 券商提交 → 事件对账 → 界面与审计。

- 意图包含 accountKey、mode、conId、side、quantity、orderType、limitPrice、TIF、clientIntentId、strategyVersion、authorizationId、sessionRevision。
- 金额和数量用 Decimal／十进制字符串传输；校验合约、币种、乘数、最小价格变动、最小数量、交易时段。
- `(accountKey, mode, clientIntentId)` 唯一；相同键和不同请求体应拒绝。双击、重复网络请求不得重复下单。
- 风控与未成交订单资金／仓位预占原子执行；多策略并发不能分别看到同一笔可用资金并同时超额下单。
- 提交状态与成交状态分开保存；超时进入 UNKNOWN／RECONCILING，禁止盲目重发。对账不能确定时停止新增风险并要求处理。
- 保存 orderId、clientId、permId 和成交记录；重复回调去重，部分成交、迟到手续费、成交更正需有可追溯处理。
- 点击撤单只表示请求发出，不能立刻显示已撤销；撤单期间仍可能成交。[IBKR 订单状态说明](https://www.interactivebrokers.com/docs/tws-api/doc/order-management/order-status/understanding-order-status-message)。
- 只允许修改本系统有管理权限的订单；外部 TWS 订单默认展示为外部订单。不得为接管订单自动绑定／撤重下；相关操作可能改变排队位置。[订单修改与绑定](https://www.interactivebrokers.com/docs/tws-api/doc/orders/modifying-orders)。
- 重启后先恢复快照、未结订单、成交和 ID 序列，完成对账后才恢复策略。SQLite 使用事务、迁移与备份恢复验证。

### 6.3 风控与真实交易授权

必须有标的白名单、单笔金额、单标的权重、总敞口、日亏损、日订单数、价格偏离、过期行情、交易时段、保证金和重复信号检查。限额未设置时拒绝实盘自动交易，不代用户选择金额。

实盘人工下单：显示真实账户与完整预览，由用户确认。实盘自动策略：用户单独确认账户、策略版本、资金上限、标的范围、限额和授权有效期；每笔都重新校验。改策略、扩范围、提高限额、授权过期必须重新授权。

紧急停止默认暂停新订单和策略；“撤销本系统挂单”“平仓”是独立操作，不把停止按钮偷偷实现成市价清仓。断线时明确不能保证撤单成功。已有风险订单仍需跟踪，不能因为策略暂停就丢失管理状态。

### 6.4 策略与回测

- 策略编辑器支持结构化配置：标的池、周期、信号、开平仓条件、仓位算法、成本假设、风控与版本说明。
- 未提供具体策略时只做明确标识的示例策略及测试，不宣称符合用户投资偏好，不自动激活。
- 历史回测、事件重放、paper、live 使用同一策略定义与信号核心，执行适配器分别实现；禁止研究 AI 直接执行任意代码访问账户凭据。
- 首期采用白名单指标／表达式配置；需要自定义 Python 时单独设计隔离、无交易密钥、网络限制、资源与超时控制，不能仅靠子进程声称安全沙箱。
- 历史数据记录来源、范围、时区、复权、缺失处理、版本与校验值。先核验已有回测引擎，不重复造轮子。
- 防止未来函数：收盘产生信号默认下一可交易时点成交；处理交易日历、停牌、拆股分红，避免复权价格与现金分红重复计算收益。
- 计入手续费、滑点和买卖价差；明确成交量约束、未成交单处理。需要做空／融资时补充借券与资金成本。
- 输出收益曲线、基准、回撤、波动、风险调整指标、换手、交易日志和成本分解；样本不足时不强行展示统计显著性。
- 固定数据与参数可复现；同一事件序列的离线重放与 paper 信号一致。回测盈利不是系统验收标准，不能承诺未来收益。

## 7. 第四部分：AI、报告与信息联动

- AI 默认只读；用户选择 paper 或 live 账户，并明确同意发送哪些数据给哪个模型服务。关闭权限立即停止新的账户上下文发送。
- 上下文使用不可变快照：账户模式、snapshotId、持仓、现金、敞口、时间、数据源及缺失项。账号脱敏，禁止携带券商凭据；仓位金额本身仍是敏感信息。
- 集中度、杠杆、盈亏归因、波动与相关性由确定性代码计算，AI 解释结果。健康评分必须公开公式和版本，数据不足显示“不足以评分”，不固定显示 75 分。
- 情景分析区分机械压力测试和预测；注明假设、历史区间、模型局限，不将 Beta 线性推算包装成确定损失。
- 周报／账户诊断报告包括摘要、账户概况、收益归因、风险、相关新闻、宏观影响、微观证据、建议、来源与限制。支持 HTML／Markdown 和 PDF 导出，保留报告版本与快照引用。
- 报告是可取消的后台任务，具备进度、失败原因与重试；重试分析不能触发重试交易。AI 超时不阻塞订单。
- AI 输出最多生成订单草稿；草稿进入同一风控与人工确认流程，不能作为自动实盘授权。
- 新闻使用现有聚合源，保留链接、发布时间、抓取时间、标的映射与去重。宏观沿用现有真实源与统计期，不把抓取日期当公布日期。
- 微观区按能力显示：资金流须披露计算口径；期权异动须有期权数据与基准；机构持仓须区分报告期与公开日期；分析师评级须有机构与时间。没有源或权限显示“未接入／不可用”，不可用估算冒充事实。
- 新闻和外部文档均是不可信数据，不能将其中指令传给交易执行器。展示文本与 Markdown 做安全渲染，禁止沿用原型的任意 HTML 注入。

## 9. 测试命令与失败场景

实施前已存在的命令（工作区根目录执行）：

```powershell
npx tsc -b --pretty false
npm run test:macro-release
npm run test:market-cache
npm run test:isolated-market-data
```

`npm run build` 当前包含 prebuild 服务准备步骤，执行前核对其副作用。真实宏观接口回归使用已有 `npm run test:macro-cards`，需可用的开发服务；离线测试通过不能替代真实源验证。

以下命令为 P0 需要新增并确保实际可运行的入口，不是当前已有功能：

```powershell
npm run test:ibkr:unit
npm run test:ibkr:e2e
npm run test:ibkr:performance
```

Python 测试建议使用现有虚拟环境；P0 先验证 pytest 依赖，再建立测试目录：

```powershell
& .\services\vibe-trading\.venv\Scripts\python.exe -m pytest services/vibe-trading/agent/tests/ibkr_terminal -q
```

所有默认测试只运行 fake broker／固定数据，禁止自动访问券商写接口。paper/live 集成测试需要独立显式参数和授权记录。缺少前提应显示 SKIP/BLOCKED，不能输出 PASS。

| 场景 | 必须得到的结果 |
| --- | --- |
| 两次相同提交、同键不同参数 | 同单返回；不同参数冲突拒绝 |
| 下单写出后网络断开 | UNKNOWN，先对账，不能自动重发 |
| 撤单与成交交错、重复成交通知 | 正确累计成交与剩余量，不虚报已撤 |
| paper 页面收到迟到 live 数据或相反 | 拒收，不串仓、不串报告 |
| 资金不足、过期报价、超限、权限缺失 | 服务端拒绝并解释，不只禁用按钮 |
| 两个策略同时使用剩余资金 | 原子预占，不能合计超额 |
| 外部 TWS 修改持仓或挂单 | 对账识别，重新评估风险，不擅自接管 |
| 服务崩溃、数据库迁移、备份恢复 | 恢复审计，先对账再启用，模糊状态保持暂停 |
| AI 超时／恶意新闻／撤销数据分享 | 订单不受影响，拒绝指令注入，停止新分享 |
| 断网、休市、无微观数据 | 明确数据状态，不填入演示值 |

订单核心至少建立以下可执行断言；接口名称在 P0 契约冻结后落地：

```python
def test_same_intent_is_sent_once(service, fake_broker, valid_paper_intent):
    first = service.submit(valid_paper_intent)
    second = service.submit(valid_paper_intent)
    assert first.intent_id == second.intent_id
    assert fake_broker.submit_count == 1

def test_live_without_authority_never_reaches_broker(service, fake_broker, live_intent):
    result = service.submit(live_intent)
    assert result.status == "DENIED"
    assert fake_broker.submit_count == 0
```

遇到缺登录、MFA、交易授权、付费行情或策略参数时：记录精确阻塞，继续独立的离线开发；当没有安全可执行工作时暂停并向用户索取最小必要信息。不能通过反复重试、扩大权限或伪造结果跨过关卡。产品长期目标状态遵守实际工具规则，不能擅自宣称完成。

## 11. 需要用户在相应阶段确定的事项

1. 交易品种与首期范围，是否接受美股／ETF 只做多起步。
2. paper 和 live 的实际连接配置与可用权限，由用户在官方客户端登录。
3. 用户自己的量化策略规则、周期和参数；自然语言先转成明确规则供确认。
4. 单笔、总敞口、日亏损、频次与有效期限；不得默认替用户决定实盘风险额度。
5. 可用行情／微观数据源及付费预算；未选择前完成接口与诚实空态。
6. AI 服务、允许分享的账户字段及调用预算；默认不向新第三方发送账户信息。

这些事项不阻止页面、离线测试与安全骨架开发，但影响真实集成和最终验收。
