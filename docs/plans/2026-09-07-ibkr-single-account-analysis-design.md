# IBKR 单次账户分析设计

## 目标

每次生成账户报告时，将脱敏后的完整 IBKR 账户快照、用户偏好、程序计算的组合指标、独立行情、历史表现和已读取的公开证据一次性提交给模型。模型只调用一次，并在一次响应中给出账户级结论；不按持仓、章节或角色重复调用模型。

## 数据流

1. “刷新账户”只负责同步 IBKR 快照与独立行情。
2. 报告任务可并行准备公开公司资料、原文和宏观证据；这些是确定性数据工具调用，不生成投资结论。
3. 服务端移除完整账户号，将全部持仓和账户指标写入一个结构化上下文。
4. 单一 CIO 提示词要求一次覆盖账户诊断、宏观周期、机会风险、三情景、行动、目标配置、监控和局限性。
5. 服务端校验单次 JSON 输出的字段、持仓覆盖和证据引用，再保存为一份报告。

## 调用与失败语义

- 每份任务的模型调用上限固定为 1。
- JSON 截断、字段缺失、未知持仓或无效引用均不会触发自动修复调用。
- 尚未调用模型的中断任务可以继续准备资料；已经调用过模型的失败任务不能续跑第二次。
- 用户重试会创建一份新的单次分析任务，并重新计入每日调用预算。

## 报告契约

新报告除原有摘要、风险、市场背景、重点持仓和行动外，还包含：基准比较，基准/乐观/悲观三情景，目标配置框架，监控指标与预警线，局限性和免责声明。旧报告字段保持可选兼容。

## 验证

- 单元测试断言 12 个持仓全部出现在同一提示词，且模型仅调用一次。
- 单元测试断言格式失败不会自动发起第二次调用。
- 服务测试断言同一失败任务不能续跑模型，主动重试创建新任务。
- 页面测试覆盖新按钮、`AI 调用 1/1`、新报告章节和旧任务取消行为。
