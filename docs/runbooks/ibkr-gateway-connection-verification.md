# Gateway 自动连接修复验证（2026-09-09）

连接流程由用户在设置页点击「智能连接」启动：按钮会完成 HTTP 桥接、API 发现、账户核对和快照同步。未连接状态不会自动探测或重试，页面也不执行两秒轮询。

实现位于 `gateway_discovery.py`、`gateway_runtime.py`、`ibkrGatewayBridge.ts` 和 `ibkrWorkbench.ts`。端口发现使用本机进程监听信息、显式 Socket 配置、已有绑定和默认候选；通过 IB 协议受管账户回报核对身份。来源切换不触发连接，重复的手动连接请求合并。连接成功后保留正常快照同步；新绑定只读，既有账户权限不会由智能连接升级；受管 paper 会话保留 clientId。

验证结果：

- 工作台单元测试 166 项通过，含无预建绑定的后台启动、实盘/模拟盘隔离、重复点击合并、旧模式响应丢弃、15 秒恢复间隔、认证 API 发现调用和过期快照状态。
- Python 终端测试 286 项通过，含实际监听端口优先级、自定义端口迁移、首次唯一账户绑定、多账户拒绝、原身份保留、断线与晚登录恢复、路由令牌及来源检查。
- 连接相关浏览器回归 7 项通过，覆盖状态显示、静默检测、模式选择、按钮行为及具体诊断可见性。
- TypeScript 检查和 Vite 生产构建通过；已有大包体积提示仍存在。
- 本机真实 Gateway API `127.0.0.1:4002` 握手匹配既有 paper 账户，成功读取净值和有效空仓快照。生产桥接 `127.0.0.1:8765` 已加载修复，网页显示“模拟盘 Gateway 已连接”。
- 使用独立临时只读客户端主动断开自身 SDK Socket，后台自动恢复并取得新的快照 ID 和会话 revision；未关闭 Gateway 应用。
- 实盘选项及智能连接按钮已验证能够拒绝把当前模拟账户当作实盘并展示原因。当前未登录真实实盘会话，因此实盘正向连接由离线回归覆盖，尚未做真实实盘登录验收。

## 模拟盘订单连接

账户页的「模拟交易」只接受 `gateway / paper`。首次连接仍以只读方式发现并核对账户；用户在 Gateway「配置 → API → 设置」取消“只读 API”后，必须在模拟交易页点击「我已取消只读，启用模拟盘订单连接」。该按钮向本机认证桥接发送一次显式确认，原子保存同一 paper 账户为 `readonly=false` 并重启受监督连接。它不创建订单，也不会修改 live 绑定；`AccountBinding` 会拒绝任何 `live + readonly=false` 配置。

订单连接成功后仍不能直接发送订单。用户必须逐项填写合约白名单、单笔名义金额、总敞口、单标的权重、当日亏损、订单频率、价格偏离、手续费预留与不超过 8 小时的有效期。系统只支持美股／ETF、整股、做多范围内的买入或卖出已有持仓、`LMT + DAY + RTH`。每笔订单先用 IBKR 实时 tick、账户快照、持仓和全部未成交订单做预览；延迟／缺失行情、过期快照、未知外部订单、超限或过期授权都会拒绝。确认和撤单分别需要一次显式点击；提交超时记为 `UNKNOWN` 并要求先对账，禁止自动重发。

CLI 备用方式：

```powershell
python scripts/configure-ibkr-gateway.py --runtime-dir .sparkflow/ibkr-terminal --gateway-port 4002 --mode paper --enable-paper-orders
```

执行 CLI 后需重启本地桥接。不得对 `--mode live` 使用该参数，脚本和绑定模型都会拒绝。
