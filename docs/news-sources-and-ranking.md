# 今日新闻：数据源与排序

## 数据接入

保留原有 10 个 RSS 来源，新增 Readhub 24 小时热榜、微博热搜、V2EX 热门、Hacker News、GitHub Trending、Hugging Face 每日论文、腾讯新闻早报、少数派和 InfoQ 中文。

接入参考为 [News Aggregator Skill](https://github.com/cclank/news-aggregator-skill)，运行时直接读取来源的公开接口或页面，不需要安装 Python 技能、不调用付费 AI，也不执行来源页面脚本。

- Readhub 仅解析 [24 小时榜](https://readhub.cn/hot) 的公开 `hot-topics` 数据，不以一周榜替代。
- Readhub、微博、V2EX、Hacker News、GitHub 保留原始名次；微博过滤广告但不重新编号。
- Hugging Face API、腾讯早报和 RSS 保留条目顺序，未声称它们有热榜名次。
- GitHub 区分今日新增 Stars 与总 Stars；微博热度、回复数、HN 积分、论文点赞分别保留单位。
- 无发布时间的热榜条目显示“时间待核验”。抓取时间独立保存，不冒充发布时间。
- 英文来源保留原题和原文摘要，不自动发送给翻译服务。

### 国际媒体（2026-08-28 核验）

国际媒体新增 10 个订阅入口；加上下文新增的 4 个社区/日报入口，以及 X 美国榜和中文筛选两个独立入口，当前内置共 35 个来源。数据来源下拉框的“国际媒体 · 聚合去重”包含国际媒体 RSS/检索及国际自定义订阅，不把 Hacker News、GitHub、Reddit、X 等社区榜单混入媒体组合。

| 媒体 | 接入方式 | 范围 |
| --- | --- | --- |
| 纽约时报 | `https://rss.nytimes.com/services/xml/rss/nyt/World.xml` | 国际 |
| BBC | `https://feeds.bbci.co.uk/news/rss.xml` | 头条 |
| BBC | `https://feeds.bbci.co.uk/news/world/rss.xml` | 国际 |
| BBC 中文 | `https://feeds.bbci.co.uk/zhongwen/simp/rss.xml` | 中文 |
| 彭博社 | `https://feeds.bloomberg.com/markets/news.rss` | 市场 |
| 卫报 | `https://www.theguardian.com/world/rss` | 国际 |
| 半岛电视台 | `https://www.aljazeera.com/xml/rss/all.xml` | 全站 |
| France 24 | `https://www.france24.com/en/rss` | 英文 |
| 华尔街日报 | Google News RSS，`site:wsj.com when:1d` | 近 24 小时检索 |
| 路透社 | Google News RSS，`site:reuters.com when:1d` | 近 24 小时检索 |

前 8 个入口为官方 RSS，后 2 个在来源说明与每条新闻中标注 Google News 检索。检索结果按 RSS 的 publisher URL 再次验证归属，仍可能收录不全或有索引延迟。华尔街日报旧官方 World/Business RSS 虽返回 HTTP 200，但最新条目停留在 2025 年 1 月，所以不把它当今日新闻。

所有新增内置国际源先按有效发布时间筛选最近 24 小时，再取至多 30 条；不补造时间、不把旧文章充当今日新闻。有效空订阅显示已连接、0 条；网页/验证页/不完整订阅显示具体错误。文章仅使用公开标题、摘要和链接，全文仍受媒体自身登录或订阅限制。评分版本 `signals-v3` 补充了英文宏观事件、政策与发布关键词，仍为规则估算。

### 社区热榜与 aibase（2026-08-28 核验）

| 来源 | 接入入口 | 口径 |
| --- | --- | --- |
| 知乎热榜 | `https://60s.viki.moe/v2/zhihu` | 60s API 第三方问题热榜，保留返回名次、原始热度及问题创建时间 |
| Reddit 热门 | `https://www.reddit.com/r/popular/hot/.rss?limit=30` | 官方 RSS 的 Popular / Hot 顺序，不是当日 Top 得票榜；RSS 不提供票数 |
| X（推特）趋势 | `https://trends24.in/` | Trends24 第三方 Worldwide 最新时间片，非 X 官方或个性化榜单 |
| X 美国榜 | `https://trends24.in/united-states/` | 固定美国地区的最新时间片前 30 名，不随 VPN 节点变化 |
| X 中文话题（筛选） | `https://trends24.in/` | 全球最新时间片前 50 名中的中文候选，保留全球原榜名次，最多 30 条；不是中国地区榜 |
| AI 新闻 · AIbase 日报 | `https://news.aibase.cn/daily` | 最近 5 个发布日的日报，每天一条，最新在前 |

知乎官方热榜 API 核验返回 401 身份未验证，Reddit JSON 返回 403；没有读取用户 Cookie 或绕过验证。知乎使用 [60s API](https://github.com/vikiboss/60s) 的公开聚合服务，Reddit 使用官方可读 RSS。X 采用 [Trends24](https://trends24.in/) 公开页面，选择带时间戳的最新榜单卡片，保留前 30 名；采样时间独立显示，不冒充话题发布时间。超过 4 小时的快照不展示。第三方服务可能有延迟，界面逐条标明提供方。

X 美国榜单独取 [United States 页面](https://trends24.in/united-states/)，同时核验页面地区标题，错地区响应作为来源错误处理。全球榜与中文筛选共用一次全球页请求，确保使用同一时间片。中文筛选在前 50 个原始名次内先筛选、后截断；只纳入含汉字且带简繁体中文特征字或中文关键词的话题，排除含日文假名、半角片假名或韩文的话题。无法判断的纯汉字短词不自动纳入。这是保守规则，仍有漏判、误判，不是全站中文热度统计，更不推断用户地区。

中文结果保留全球名次（例如 #7、#31），不重编号成虚构的中文官方名次。全球、美国和中文筛选出现同一话题时聚合去重，单来源视图恢复各自的名次及热度。有效快照没有匹配项显示“暂无匹配的中文话题”，来源仍为已连接；地区不符、结构变化、网络失败或快照过期则明确报错，不用旧榜补位填充空榜。

`aibase` 仅解析 Nuxt 数据中的 `getDailyNews` 列表，按有效发布时间倒序、北京时间日期及 ID 去重，选择最近 5 个发布日的日报，再并行读取对应的 `getDailyNewsDetail` 正文，绝不从 `getAIHotRank` 或相似文章补位。源时间 `YYYY-MM-DD HH:mm:ss` 明确按 UTC+8 解析，列表和正文均核验日期；保留日报标题和正文目录摘要，不拆成具有虚假文章地址的单条新闻。

- 根据用户最新要求，展示最近 5 期，每天一条。今天未发布、周末或节假日就向前取已发布日报；不足 5 期时只展示实际可用条目，不虚构补齐。
- 列表最多保留 5 期，未来发布时间和无法核验日期的条目不会被选中。详情日期仍保留为实际发布时间，不冒充今天发布。
- 入口位于微博热搜正下方，标注实际期数。条目标注“今日日报”或“往期日报”及日期。成功获取旧日期日报不算缓存故障；任一期详情抓取失败时沿用通用 30 分钟失败缓存政策，保留上次完整快照并标注缓存。
- 仅在日报列表为空或无有效候选时显示“暂无可用日报”；结构变化、网络失败单独显示错误。
- 不创建定时任务，不生成外部推送。后续进入页面或手动刷新时获取最近 5 期，并复用现有聚合缓存。

### 自定义订阅

页面展开“管理数据源 / 添加订阅”，填写名称、公开 HTTPS RSS/Atom 地址、分类与地区，验证至少一条有效记录后保存。支持移除确认；内置来源不在自定义移除范围内。暂不支持 OPML 批量导入（上游技能支持 OPML 文件，与本页面入口不同）。

- 配置保存于本项目 `.sparkflow/news-sources.json`，已被 Git 忽略；重启后读取。最多 20 个。写入串行化并使用临时文件原子替换，不覆盖损坏配置。
- 自定义源只直连，不走本地代理；仅 HTTPS 标准端口，无 URL 用户名密码，禁止内网、环回、特殊用途地址及 IPv6。每次抓取及每个重定向解析并固定公网 IPv4 DNS 地址，拒绝私有地址、外部实体与 DTD。
- 抓取总超时 12 秒、响应最多 2 MB、至多 3 次重定向。仅 UTF-8 XML；普通网页 URL 不能代替订阅地址。
- POST/DELETE 仅接受当前应用同源 JSON；添加前验证内容，修改配置后重新建立新闻快照。自定义来源基准为 55，不凭用户命名提升可信度。
- 自定义源不强制近 24 小时，保留原始日期（适用于低频博客）；没有热榜名次或热度时不虚构。

## 排序规则

| 模式 | 规则 |
| --- | --- |
| 原榜顺序 | 单来源按原始名次／条目顺序；全部来源按来源分组，不比较跨平台名次 |
| 重要程度 | 来源基准占 35%，事件影响占 65%；规则估算，不是来源官方评分或事实核验 |
| 热度优先 | 有原榜时使用 `100 × exp(−(名次−1)/20)`；论文点赞在来源内做对数归一化 |
| 时间最新 | 按有效发布时间倒序，缺失时间置后 |
| 综合权重 | 重要程度 55% + 时效 25% + 热度 20%；缺失维度剔除后重新归一化 |

时效为 `100 × exp(−小时数/36)`。缺少发布时间时，综合权重额外扣 8 分；失败缓存额外扣 10 分。

事件影响依据宏观政策、公共安全、具体发布及科技产业进展等规则估算。预测和未证实信息的重要程度上限为 58，观点类上限为 65，娱乐话题上限为 42。规则判断可能误判，界面可展开查看具体依据。热度既不代表重要性，也不代表可信度。

## 去重、筛选与容错

- 对规范化 URL 和一致的长标题进行精确合并，不声称完成语义事件聚类。
- 每条合并记录保留各来源的完整版本；切换到单来源后恢复该来源原始名次、热度及评分依据。
- 分类计数基于当前来源过滤后的实际条目，不使用接口截断前的计数。
- 单来源限量约 10–40 条；不再把整个总榜截为 80 条。页面按 60 条渐进展示。
- 接口缓存 2 分钟，手动刷新至少间隔 15 秒，并发请求共用同一次拉取。
- 失败时最多保留 30 分钟的上次成功数据，显示缓存状态和原获取时间，不显示为连接成功。
- 单来源最多等待 20 秒，不让一个慢源阻塞整个页面；公开页面结构改变时返回来源错误，不伪造条目。

## 维护与验证

- `server/newsFeed.ts` 定义新增来源、解析器、评分和缓存服务。
- `server/newsSubscriptions.ts` 定义自定义订阅校验、受限公网抓取和本地持久化；`SignalsSourceManager.tsx` 提供订阅管理界面。
- `src/lib/newsPresentation.ts` 定义筛选、来源投影和客户端排序。
- `node scripts/verify-news-feed.mjs` 验证解析、原榜名次、评分、去重、超时及缓存。
- 同一脚本覆盖知乎来源校验、Reddit RSS、X 最新快照、aibase 最近五期选择、同日去重、详情并行读取、昨日回退、周末保留、真实日期及跨午夜缓存与客户端展示。
- X 扩展测试覆盖美国固定地区校验、中文简繁体筛选、日文/韩文排除、筛选后原始名次、同话题多榜投影、共用请求、正常空榜与错误缓存。
- `node scripts/verify-news-presentation.mjs` 验证排序、分类统计和时间格式化。
- `npm run build` 验证 TypeScript 与生产构建。

新增或调整来源后，还应实测 `/api/news-feed?refresh=1` 的来源状态，并在页面检查原榜与重要程度排序。
