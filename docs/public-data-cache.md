# 公共数据预加载与共享缓存

## 使用

在运行 SparkFlow 的 Windows Mini 上，先停止旧服务，在项目目录切到功能分支，再使用原启动脚本启动：

```powershell
git fetch origin
git switch codex/public-data-preload-cache
git pull --ff-only
.\start-sparkflow.bat
```

如果存在未提交修改，先保留并处理冲突，不要使用强制重置。Cloudflare Tunnel 的域名、端口和 Token 不需要因为缓存功能而修改；服务仍在原端口运行。

本功能默认开启，不需要 Redis、不需要浏览器一直开着。首次启动尚无有效快照时仍需真实抓取数据；缓存准备好后的访问才不会等待上游。没有替你在 Mini 上安装自动部署任务，也没有将 Vite 数据服务改造成独立生产后端。

## 数据流程

```text
服务启动 → 恢复未过期硬盘快照 → 排队预加载常用公共数据
                                   ↓
后台调度器 → 有限并发刷新 → 校验 → 更新内存和硬盘
                                   ↓
访客请求 → 有效缓存立即返回 → 页面显示
           ├─ 到刷新时间：先返回上次数据，后台更新
           └─ 无缓存/已过硬期限：等待抓取；超时返回 503，不伪装实时
```

- 同一数据同时被多个访客请求，只执行一次加载。
- 刷新失败不覆盖已有有效数据；5 秒起指数退避，最长 5 分钟。
- 公共刷新独立于原接口的无限期“上次成功值”回退；明确标记 `stale` 的回退结果不能重新续期。某个分区部分来源失败时，可返回仍可用的数据，缺失项保留不可用状态。
- 默认慢数据最多 **2 个资源加载任务**同时执行，实时行情另有 **4 个独立槽位**，避免新闻/宏观慢源堵住行情。单个加载器内部仍可能并行请求多个来源，这不是上游 HTTP 连接数上限。
- 常用市场总览、主要指数、中国宏观四分区、全球宏观六分区、中国费雪存款口径/GDP/收入启动预热。
- 其他白名单资源首次请求后进入后台刷新，30 分钟无人使用则暂停。不会预先遍历全部股票或区县。

## 覆盖与隔离

| 范围 | 策略 |
| --- | --- |
| 公共市场总览、指数、全球/中国宏观、公共政策新闻 | 共享缓存；常用分区预热 |
| A股/港股/美股及支持的国际市场热力图 | 按需加入，近期使用时后台刷新 |
| 加密市场热力图 | 服务启动预热；CoinGecko 异常时切换 CoinPaprika；近期有效快照后台刷新 |
| 核心指数、汇率、VIX/黄金等资产、美国宏观指标、流动性、金融条件 | 按需加入，独立缓存和失败隔离 |
| GDP、收入、费雪利率 | 共享缓存，但来源 `validUntil` 优先，发布边界后不提供旧快照 |
| 估值、比特币周期、港美市场内容、交易所运行状态 | 按资源频率刷新 |
| 每日简报、简报详情、今日新闻 | 独立页面缓存，见下节；不进入公共白名单 |
| 账户、持仓、交易、个人 AI 研究、密钥、订阅管理 | **不进入此共享缓存** |
| 区县政务、证券搜索、SSE 推送 | 保持原有链路，不做全局 GET 缓存 |

市场页使用新接口 `/api/public-market-intelligence`，只读取内置新闻来源。原 `/api/market-intelligence` 保持原行为；`/api/news-feed` 使用独立的订阅配置缓存，自定义订阅不会混入公共快照。有限白名单及资源周期定义在 `src/lib/publicDataPolicy.ts`，加载器映射在 `vite.config.ts`。

## 每日简报与今日新闻

- 每日简报按北京时间每天 09:00 更新；启动时恢复当天版次，09:00后关机错过的版次会补齐。正常访问复用本日快照，不因缺失可选来源或分析每5分钟重生成整页。额外 AI 摘要继续走独立缓存；手动“刷新全部数据”仍可主动重生成。
- 今日新闻启动时恢复有效快照并预加载，每 2 分钟后台更新；软过期先返回旧快照，最长保留 30 分钟。北京时间跨日、失败来源原始有效期会进一步缩短期限，不给旧新闻重新续期。全部来源失败不覆盖有效快照。
- 新闻缓存按本项目当前订阅配置生成指纹，增删订阅后替换缓存；固定保存为 `.sparkflow/news-page-cache/` 内的一个哈希文件（上限 8 MiB），不累积历史订阅快照，不保存代理连接配置。此目录可能包含自定义订阅内容，不属于公共共享目录。
- 浏览器只在当前标签页内存中复用这两个页面及简报详情，直接复用窗口 15 秒；返回页面可先展示仍有效的缓存，再向服务端检查更新。不会把整页简报或新闻写入 localStorage。额外 AI 摘要改由下述服务端缓存负责复用。
- 页面可见时，新闻每 30 秒、简报每 60 秒检查服务器缓存；切回标签页也会检查。离开页面会取消该页面的等待，但不影响其他使用者共用的请求。
- 点击“刷新新闻”跳过浏览器缓存，并按原有 15 秒最短间隔请求上游；“刷新全部数据”保留简报原有强制生成行为，并清除相关页面缓存。订阅管理与 AI/账户/交易 POST 不进入读取缓存。
- 每日简报以北京时间09:00切换版次：此前读取昨天缓存，此后只接受当天版次；打开、页面保持打开跨越09:00以及恢复可见时均校验。当天生成失败显示待更新，历史文件保留但不冒充当日数据。校验版次日期与生成日期，不能仅替换日期标签。简报详情以生成时间起6小时为期限；新闻软过期会有提示。休市行情和低频指标保留真实观察日期，不伪造当天成交。
- 缺失数据按标的/来源接口独立补齐，最多两个并发任务；成功字段保持冻结，不重生成整份简报或AI正文。失败项独立退避30秒至5分钟，服务端每分钟检查到期任务，访客请求也可触发检查；无授权配置的来源明确标为阻塞。补齐和重试状态原子写回同版次磁盘缓存，跨访客、服务重启复用；生成时间不变，实际补齐时更新updatedAt。跨版次或完整重生成后的旧修复结果不覆盖新缓存。

页面缓存与上述公共缓存开关独立，默认开启；服务端响应仍是 `private`，不进入 CDN 共享缓存。新闻使用 `private, no-store`；简报复用既有 `.sparkflow/daily-brief/` 版次快照。

### 简报额外 AI 摘要

`POST /api/daily-brief/ai-summary` 现在使用独立服务端缓存：同一台 SparkFlow 服务的多个访客，读取相同版次、相同输入内容和模型配置时，共用一次成功的生成结果；首次未命中时仍需等待模型生成。并发访问合并为同一个任务，不因浏览器关闭或取消等待而取消其他访客的生成。

- 缓存键包含简报日期、时段、生成时间、内容指纹、提示词版本，以及服务端保存的模型连接配置指纹。手动刷新产生新版简报，或更换模型、提供方、接口地址、协议、密钥、代理配置后，不会误用不匹配的旧摘要。
- 成功结果保留到本版次次日北京时间 09:00。返回原始摘要生成时间，不把缓存读取时间伪装成生成时间。来源简报过期时不生成新摘要，也不把旧摘要当作当期结果。
- 内存最多 4 份，单份不超过 256 KiB；最多同时生成 2 个不同键。`.sparkflow/daily-brief-ai-summary/` 内只保存一个原子替换的快照文件，有效快照可在重启后恢复。该文件不保存密钥、接口地址、提示词和原始输入；仍属于本项目页面数据，不进入公共/CDN 白名单。
- 模型报错、字段不完整、超大输出不会写成成功缓存；同一失败请求从 30 秒起退避，最长 5 分钟。磁盘不可用时仍可使用内存缓存。
- 浏览器不再信任旧版 localStorage AI 摘要，也不再写入这种缓存。每次进入页面请求服务端确认结果，并核对摘要对应的版次，防止模型切换、页面更新或迟到响应导致错配。原有浏览器存储条目未删除，但不再读取。
- 此服务只接受服务端当前的非个人化简报，不使用访客传入的 prompt/模型设置/持仓作为生成输入；含个人持仓的简报拒绝进入跨访客缓存。响应为 `private, no-store`。账户、交易、其他 AI 对话仍不走这个缓存。

这不是跨多台后端的分布式缓存。内网穿透需指向同一个运行新版代码的 SparkFlow 服务；只部署静态 `dist` 文件不会运行上述 API 缓存逻辑。

## 更新与有效期

| 类别 | 常见刷新周期 | 最长缓存年龄（来源边界可能更短） |
| --- | --- | --- |
| 主要指数快照、全球行情推送 | 3 秒 | 90 秒 |
| 中国宏观指数 | 3 秒 | 120 秒 |
| 股票热力图、独立指数/汇率/资产、国际市场总览 | 3 秒 | 180 秒 |
| 全球市场/商品完整分区（补充历史曲线，现价由快速行情覆盖） | 60 秒 | 180 秒 |
| 加密市场热力图 REST 快照 | 60 秒 | 15 分钟（浏览器实时流每 3 秒合并，市值名单内部每 15 分钟更新） |
| 宏观分区与公共新闻 | 通常 120 秒 | 按资源为 15–30 分钟 |
| GDP | 1 小时 | 1 小时，且受来源有效期限制 |
| 估值 | 15 分钟 | 1 小时 |

这些是调度目标，任务排队和上游速度可能延迟刷新。缓存保存时间不是行情成交时间、指标发布日期或数据核验时间；原始时间及口径不会被改写。最后一次成功抓取的旧报价也不能因为重新存盘变成“实时成交价”。

### 实时行情与缓存同时工作

- 进入页面先展示仍有效的缓存；股票、指数、黄金、原油、主要汇率、BTC/ETH 等可见行情每 3 秒检查服务端新快照。浏览器不再对这些 3 秒资源额外复用 15 秒响应。加密热力图沿用实时流每 3 秒合并、REST 每分钟补底的专用链路。
- 服务端采用开始到开始的 3 秒目标周期，250 毫秒调度检查；同资源请求合并、单次未完成不重叠。全球行情卡片共用批量快速帧，中国指数不再等待一个月历史数据。快速来源首次等待最多 2.5 秒，慢源短暂跨帧复用最多 6 秒，不无限续期。
- BTC/ETH 卡片同时复用市场行情已有的 Binance/OKX 批量来源；Yahoo、CoinGecko 或 Binance 单一路径超时，不会遗漏可用的 OKX 报价。模拟下单区的股票展示轮询也改为 3 秒，其独立报价缓存降到 2.5 秒；不改变券商下单、买卖价校验与账户权限。
- 卡片失败后继续重试，取消原有连续三次失败后停止更新的逻辑；隐藏标签页暂停行情轮询，恢复可见立即检查。全球推送静默超过 12 秒切换 HTTP 轮询。数据合并按报价自身时间排序，历史分区或迟到响应不覆盖较新的价格。
- 内存行情及时更新；磁盘行情快照最多每 30 秒保存一次，减少高频写盘。重启只恢复仍在硬期限内的快照，不影响正常运行的 3 秒内存更新。
- 上游超时、限流继续退避，保留有界最后成功快照；休市、免费源延迟、源站自身更新较慢时，不能承诺每 3 秒出现新成交价。账户和交易数据仍不进入公共缓存，订单提交逻辑不变。

回归检查：`npm run test:realtime-quotes`、`npm run test:public-cache`、`npm run test:isolated-market-data`，以及 `tests/ibkr/public-data-cache.spec.ts`。本地实测采样可使用 `node output/cache-audit/realtime-live.mjs realtime-after.json`（审计目录不作为运行依赖）。

响应保留原有 JSON 字段，另附 `_publicCache`：`state`、`storedAt`、`refreshAt`、`expiresAt`；也有对应 `X-SparkFlow-Cache-*` 响应头。不再显示底部全局缓存提示条；分区错误、卡片待更新、数据源时间和来源本身的 `snapshot`、`delayed` 等标识依然保留。移除提示条不改变刷新、失效或失败重试策略。

服务器对这些响应发送 `Cache-Control: no-store`：共享的是 Mini 后端缓存，不是把所有 API 放进 Cloudflare CDN。不要给账户/交易接口设置“缓存所有内容”。

## 浏览器与页面切换

只在显式接入的公共请求上进行内存复用，不修改全局 `fetch`。慢数据直接复用窗口最多 15 秒，实时行情窗口为 0，每次轮询向服务器取最新缓存。页面初始绘制可先恢复尚未过硬期限的上次结果，再重新验证。某个页面取消请求不会取消其他页面共用的传输。手动刷新可跳过浏览器内存，但不能让每个访客强制抓取上游。

后端 `_publicCache.expiresAt` 同样约束热力图会话缓存和日级估值缓存。该功能不会把已过期缓存当成可用快照重新加载到页面；已显示的部分面板可能保留最后结果，但会提示不可用/过期，应以数据源时间为准。

## 存储和资源预算

- 路径：项目目录 `.sparkflow/public-data-cache/`（已被 Git 忽略）。仅保存通过校验的公共 JSON，不保存请求凭据。
- 内存：服务器最多 160 条、约 32 MiB **序列化数据预算**，单条约 2 MiB；实际进程堆内存还包含对象和既有数据服务。
- 浏览器：最多 100 条、约 16 MiB 字符串预算；不持久化到 localStorage。
- 每个固定资源对应一个 SHA-256 文件名；不使用用户输入作为文件路径。临时文件写完后替换正式快照，损坏/版本错误/超限/过期文件不会恢复。
- 硬盘满或无写权限时，内存缓存仍可工作，状态接口会增加 `diskErrors`。
- 关机后 CF Tunnel 无法让后台继续运行；本功能解决等待和重复抓取，不解决供电、宽带或上游限流。

## 开关与检查

在 `.env.local` 设置后重启服务：

```dotenv
SPARKFLOW_PUBLIC_CACHE=1
SPARKFLOW_PUBLIC_PRELOAD=1
SPARKFLOW_PUBLIC_CACHE_CONCURRENCY=2
```

- `SPARKFLOW_PUBLIC_CACHE=0`：完全关闭新后端缓存，回到原公共加载器；浏览器仍保留短期复用。
- `SPARKFLOW_PUBLIC_PRELOAD=0`：不主动预热常用资源；访问过的资源仍按需刷新。
- `SPARKFLOW_PUBLIC_CACHE_CONCURRENCY=1`：较弱 Mini 可降低后台资源并发。

访问同源 `/api/public-data-cache/status` 查看任务数、缓存容量、各公共资源状态、是否预热、失败次数和过期时间。它是只读诊断接口，不支持远程清除/强制抓取，不暴露本机路径、Token 或上游错误详情。
