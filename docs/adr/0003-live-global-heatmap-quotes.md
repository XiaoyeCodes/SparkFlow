# ADR-0003: 海外市场热力图采用五秒盘中批量快照

## Status

Accepted

## Context

A 股、港股和美股热力图已有各自的高频行情链路；日本、韩国、印度、澳大利亚、欧洲、英国和沙特热力图此前通过 Yahoo 日线接口逐股读取。该接口使用最后一根日 K 收盘值计算涨跌幅，前端缓存 60 秒、服务端缓存 45 秒，且弹窗打开后不继续刷新，因此会与地球上的四秒指数行情出现口径和时间差异。

海外交易所的免费公开行情还可能存在交易所级延迟。刷新频率只能提高“检查新数据”的频率，不能消除上游授权造成的 15–20 分钟延迟。界面必须展示实际数据时间和延迟状态，不能把延迟行情标记为实时。

## Decision

- 海外热力图使用 Yahoo Spark 的 `1d / 5m` 批量快照，一次请求同一市场最多 10 个成分股。
- 价格使用 `regularMarketPrice`，涨跌幅统一相对 `chartPreviousClose` 计算；日线接口只保留为单股降级源。
- 弹窗可见时采用完成后再计时的五秒递归刷新，页面隐藏时暂停请求，避免重叠轮询。
- 前端缓存 2.5 秒、服务端缓存 3 秒，并以共享 in-flight Promise 合并预取、鼠标悬停和弹窗轮询产生的并发请求。
- 页面加载后以三路并发预热支持的国家市场，缩短第一次打开时间。
- API 返回 `refreshIntervalMs`、`quoteStatus`、`sourceDelaySeconds`、`session` 和每只股票的 `updatedAt`；界面明确显示“盘中 5 秒刷新”“源延迟约 N 分钟”或“已收盘”。
- 地球上的全球指数继续使用 ADR-0002 的四秒增量行情流。热力图与地球指数都采用盘中快照口径，但允许因数据供应商和交易所授权不同产生可见延迟。

## Consequences

### Positive

- 海外热力图不再使用日 K 收盘值冒充盘中行情。
- 一个国家每五秒最多产生一次批量上游请求，而不是十个逐股请求。
- 打开的热力图会持续更新，预取与轮询共享缓存，不会形成请求风暴。
- 用户可以看到真实数据时间以及上游延迟，能区分“页面没刷新”和“行情源延迟”。

### Negative

- 免费数据源仍可能延迟、休市或限流；五秒是采集节奏，不是交易所逐笔实时 SLA。
- 同时预热多个市场会增加启动后的短时网络负载，因此并发限制为三。
- 当前缓存仍是单进程内存缓存，多实例部署需要共享缓存。

### Neutral

- A 股、港股和美股热力图保持原有数据链路，不受此次调整影响。
- 代表性成分股与权重仍为静态配置；本 ADR 只改变报价新鲜度和刷新方式。

## Alternatives Considered

- 将日线接口轮询间隔直接改为五秒：请求更频繁但数据仍是日 K，无法解决口径错误。
- 每只股票独立轮询：上游请求量扩大十倍，容易限流且同屏时间点不一致。
- 所有国家接入付费交易所逐笔流：实时性最佳，但需要交易所授权、密钥和持续成本，当前项目没有这些凭据。
- 永远返回旧缓存并后台刷新：打开速度快，但弹窗无法确定何时拿到新值，因此改为三秒缓存后等待一次批量刷新，失败时才回退最近成功快照。
